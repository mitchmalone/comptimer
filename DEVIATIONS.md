# Deviations

Where this project diverges from the jig standard. Every entry has a justification and, where the divergence should eventually close, a trigger. Deviations are documented, never silent — an empty file means full compliance.

| Deviation                                                                                 | Why                                                                                                                                                                                                             | Reconverge when                                                                                                                                                            |
| ----------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `apps/mobile` is Expo React Native + EAS/TestFlight — a surface the jig has no flavor for | The judge controller must be a real phone app (camera QR pairing, lock-screen survival, App Store delivery). Delivery conventions in `docs/DECISIONS.md` (2026-07-30, EAS entry)                                | The jig grows an Expo flavor — this repo and backcountrygames are its inputs; hand learnings to the jig, don't localize them                                               |
| Four Vercel projects (web, api, admin, marketing) instead of two per product              | Grew one surface at a time in Phase 1; api-as-separate-project predates the standard's "API as functions inside the app project". Works, and consolidation risks the pairing/realtime spine for zero user value | Next structural change to `apps/api` or `apps/admin` — fold api into the web project as `/api/*` functions and admin in behind it (or record why not, dated, in DECISIONS) |
| No Better Auth — no auth at all beyond a hardcoded admin password in env                  | Deliberate no-login product (see `docs/DECISIONS.md` and ROADMAP §Phase 7); identity for v1 is an anonymous device-scoped ID                                                                                    | Phase 7 (payments need identity): adopt Better Auth in `apps/api` unless RevenueCat's anonymous IDs make it unnecessary — decide and record then                           |
